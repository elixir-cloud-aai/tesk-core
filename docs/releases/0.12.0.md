tesk-core 0.12.0 brings the taskmaster and filer side of TES 1.1 outputs with wildcards and `path_prefix`, executors whose errors are ignored, and logs of the uploaded output files, each of which a TESK API release reports. The filer's pods are hardened and can take the FTP credentials from a secret by reference, the taskmaster of a cancelled task stops its jobs on `SIGTERM`, and the filer jobs are labelled with their task. **Operators must act on several changes, and on the upgrade order with the TESK API**: before you upgrade, read the [upgrade notes for 0.12.0](https://tesk.readthedocs.io/en/latest/tesk-core/upgrading/#0120), in particular "Upgrade order for the filer job labels": deploy a TESK API that includes [tesk-api#183](https://github.com/elixir-cloud-aai/tesk-api/pull/183) first, then switch the taskmaster image.

## Breaking changes

- Filer jobs have the label `taskmaster-name: <task>`, as the executor jobs have, so selectors on `taskmaster-name` alone now also match them; this taskmaster needs a TESK API that includes [tesk-api#183](https://github.com/elixir-cloud-aai/tesk-api/pull/183), which selects a task's executor jobs by `job-type: executor` too: deploy that TESK API first, then switch the taskmaster image (#147, #155)
- Filer pods run with a restricted security context (non-root, `RuntimeDefault` seccomp profile, no privilege escalation and capabilities, read-only root filesystem with a writable `/tmp`); if they fail to start or can't write a task's volume, set `FILER_POD_SECURITY_CONTEXT` or `FILER_SECURITY_CONTEXT` in the taskmaster's environment (`{}` restores the old behaviour) (#113, #141)
- S3 and FTP `DIRECTORY` outputs, and matches of outputs with wildcards, that contain names with `#`, `?`, a tab or a line break (or `;`, for FTP), or names that aren't valid UTF-8, fail and upload nothing, instead of uploading to truncated or changed keys or paths; tasks that write such names should rename them (#146, #149)

## Features

- Outputs with wildcards and a `path_prefix` (TES 1.1) are expanded by the filer for every scheme, each match uploaded below the output's URL; the taskmaster mounts them at the pattern's deepest directory without wildcards and refuses patterns with wildcards in their first component (#134)
- The taskmaster goes on after a failed executor whose job has the annotation `ignore-error: "true"`, which a TESK API that accepts `executors[].ignore_error` sets (#142, #143)
- The outputs filer prints the files it uploaded, and the taskmaster stores them as the annotation `output-file-logs` of the outputs filer's job, for a TESK API to report as `logs[].outputs` (#144, #145)
- `TESK_FTP_SECRET_NAME` makes the filer's jobs reference the secret with the FTP credentials instead of holding them as values, `FILER_RESOURCES` sets the filer's resource requests and limits, and filer pods have the labels `app.kubernetes.io/component: filer` and `app.kubernetes.io/part-of: tesk` (#113, #141)

## Fixes

- On `SIGTERM`, the taskmaster of a cancelled task stops the task's running jobs, deletes its PVC (unless `KEEP_FAILED_PVC` keeps it) and exits with code 0, so that a task cancelled just after its taskmaster started no longer leaves its executor running (#132, #139)
